Case Intelligence · Snowflake CoCo Hackathon · Track 2

Five systems. One angry customer.
No shared key.

One customer with one problem contacts support five times, in five different systems. Together, those five records are one case: the full story of that problem. But nothing in the data connects them. No ticket number, no shared ID. The tools see five unrelated complaints, so every count and every dollar figure built on this data is wrong.

The linking rule

Three signals must agree.

Identity

who the record names: a fuzzy surname, an address, an order that resolves to a customer

+

Time

a case is a bounded episode: hours, not weeks. A silence ends it

+

Meaning

what the complaint is about: embeddings over the extracted issue, never keywords

And the reasoning is kept: every link lands in a table: which records, which signal, how similar, how far apart. Ask “why are these one case?” and it answers from its own evidence.
